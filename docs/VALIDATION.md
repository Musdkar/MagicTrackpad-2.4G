# 验证与测试计划

本文规定从真实设备研究到完整无线桥接的验证步骤。所有“通过”都必须有原始日志、抓包或测试记录支持。

## 0. 测试原则

- 先测试 USB，再测试无线。
- 先测试有线 USB HID 模拟，再测试无线端到端。
- 所有性能数字必须注明测试条件、固件版本、信道、距离和样本量。
- 不以“鼠标能移动”作为多点触控兼容的通过标准。
- 每个阶段都保留可复现的测试数据。

## 1. M0：真实妙控板 USB 协议采集

### 目标

确认目标 USB-C Magic Trackpad 的真实 USB 速度、设备身份、描述符、报告格式、Feature Report 和时序。

### 测试环境

优先使用 Linux 主机和 USB-C 数据线；也可使用 USBPcap / Wireshark 或硬件 USB 分析仪。不要只依赖系统设置中的设备名称。

### 采集项目

| 项目 | 必须记录的内容 |
|---|---|
| 设备身份 | VID、PID、bcdUSB、设备版本、字符串描述符 |
| 总线速度 | Low-Speed / Full-Speed / High-Speed |
| 配置 | Configuration、Interface、Alternate Setting |
| HID | HID Descriptor、完整 Report Descriptor |
| 端点 | Interrupt IN 地址、最大包长、Interval |
| 控制请求 | GET_REPORT、SET_REPORT、其他实际出现的请求 |
| 多点触控 | 报告 ID、前缀长度、每触点字段、触点 ID |
| 时序 | 报告间隔分布、连续移动时报告频率 |
| 电源 | VBUS 电压、电流、插拔瞬态 |

Linux 初步检查命令：

    lsusb -t
    lsusb -v -d 05ac:0324

使用 usbmon / Wireshark 记录完整 USB 控制传输与 Interrupt IN 数据。若系统没有识别为 05ac:0324，先按实际 VID/PID 搜索，不要假设设备 ID。

### M0 通过标准

- 确认设备实际 USB 速度。
- 保存原始设备、配置、接口、端点和 HID Report Descriptor。
- 保存至少一组无触摸、单指、双指、多指、点击和抬起的原始报告。
- 找到并记录多点触控启用请求及其完整 Setup Packet。
- 明确最大 Input Report 长度和报告间隔分布。

**停止条件：** 如果目标设备为 High-Speed，而当前 Host MCU 只支持 Full-Speed / Low-Speed，暂停 ESP32-S3 Host 路线并重新选型。

## 2. M1：发射端 USB Host

### 目标

让 ESP32-S3 独立连接真实妙控板，完成枚举、初始化和原始报告采集。

### 测试项

- USB-C Host 角色和 VBUS 供电正确。
- 插入设备后可自动枚举，拔出后可清理资源。
- 能读取并保存 HID Report Descriptor。
- 能发出已确认的 Feature Report 初始化请求。
- 能持续获取 Interrupt IN 原始报告。
- 不修改触点数据，不转换为普通鼠标事件。
- 连续运行 2 小时无 USB Host 崩溃、内存泄漏或任务卡死。
- 设备重新插拔后能自动恢复。

### M1 通过标准

将 ESP32-S3 获取到的原始报告保存到文件，与 Linux USB 抓包中的对应报告逐字节对比。若 Host HID 组件对 Report ID 做了处理，必须明确恢复或适配方式。

## 3. M2：接收端 USB HID Device 与 macOS 原生识别

### 目标

不接入无线链路，先让接收端通过 USB 向 macOS 呈现一个模拟的 USB-C Magic Trackpad。

### 测试项

- 接收端能够枚举为 USB HID Device。
- 设备描述符、配置描述符、接口、端点与 HID Report Descriptor 与目标设备匹配。
- 能处理 macOS 发来的必要 HID Feature Report 请求。
- 使用录制的原始 Input Report 测试数据驱动接收端。
- macOS 系统 USB 设备树能看到预期设备。
- 验证系统是否绑定预期的 Apple 触控板驱动。
- 验证单指移动、点击、双指滚动、缩放、三指和四指手势。
- 设备断开、重启和重新连接后能恢复。

### M2 通过标准

macOS 不仅能看到设备名称，还必须能使用原生触控板多指手势。若只显示普通鼠标或只能移动指针，M2 不通过。

### 重要说明

USB VID/PID、字符串和描述符的模拟只用于本项目兼容性实验。必须先用真实设备抓取并确认描述符，不要仅凭设备名称自行构造。

## 4. M3：ESP-NOW 无线链路

### 目标

在两块 ESP32-S3 之间传输测试报告，不连接妙控板、不接入 macOS 触控板驱动。

### 测试项

- 固定信道和 Peer 配置。
- 单包发送 32、64、128、160、200、238 字节测试载荷。
- 记录发送回调、接收回调、序号缺口、重复包和乱序。
- 分别测试 0.5 m、1 m、3 m、5 m 距离。
- 测试不同方向、遮挡和 USB 3.x 设备附近的干扰。
- 测试 2.4GHz Wi-Fi 拥挤信道。
- 验证无线断开后自动恢复。
- 验证协议包长度检查，不允许静默截断。

### M3 通过标准

- 最大目标报告长度能够完整传输。
- 在目标使用距离内无持续性丢包。
- 延迟分布可重复测量。
- 队列不会在无线短暂拥塞后持续积压旧报告。

## 5. M4：完整端到端

### 目标

完成 Trackpad USB → Transmitter → 2.4GHz → Receiver → macOS USB HID 的全链路。

### 必测项目

| 类别 | 测试 |
|---|---|
| 基础输入 | 单指移动、点击、按下、抬起 |
| 多点触控 | 双指滚动、缩放、旋转（系统支持时）、三指与四指手势 |
| 压力/触点 | 不同触点数量、接触面积与压力变化 |
| 连续性 | 快速移动、快速滚动、连续点击 |
| 无线 | 距离、遮挡、干扰、信道切换 |
| 恢复 | 发射端重启、接收端重启、妙控板拔插 |
| macOS | 睡眠/唤醒、锁屏/解锁、重启后重新识别 |
| 稳定性 | 至少 8 小时连续输入与空闲混合测试 |

## 6. 延迟测量方法

在固件中为每份报告记录：

- T0：发射端 USB Host 完成一次 Input Report 接收。
- T1：发射端提交无线发送。
- T2：接收端收到并通过校验。
- T3：接收端把报告提交给 USB HID IN 端点。

计算：

- USB Host 后处理：T1 - T0
- 无线链路：T2 - T1
- 接收端排队与 USB 提交：T3 - T2
- 桥接新增延迟：T3 - T0

由于两块 MCU 的单调时钟不天然同步，初期优先使用 GPIO 测试点配合逻辑分析仪测量；软件时间戳需要先做时钟偏移与漂移校准。

每次测试至少输出：

- 样本数量
- P50 / P95 / P99 / 最大值
- 序号缺口数量与比例
- 重传次数
- 队列峰值与溢出次数
- 测试距离、信道、固件版本和供电条件

第一版目标是桥接新增延迟 P95 ≤ 3 ms、P99 ≤ 5 ms。该指标不包括妙控板内部采样时间、macOS 事件处理和屏幕渲染时间。

## 7. 测试记录模板

每次测试创建一份记录，至少包含：

| 字段 | 内容 |
|---|---|
| 日期 | 测试日期与时间 |
| 硬件 | 开发板型号、芯片版本、天线 |
| 固件 | Git commit、ESP-IDF 版本 |
| 设备 | 妙控板 USB VID/PID、USB 速度 |
| 环境 | 距离、遮挡、Wi-Fi 信道环境 |
| 输入 | 单指、多指、点击或压力测试 |
| 延迟 | P50、P95、P99、最大值 |
| 丢包 | 发送数、接收数、序号缺口 |
| 结果 | PASS / FAIL / BLOCKED |
| 证据 | 日志、USB 抓包、逻辑分析仪截图 |

## 8. 当前优先级

1. 找到并连接真实 USB-C 妙控板，完成 M0 协议采集。
2. 验证 ESP32-S3 是否能以 USB Host 稳定读取它。
3. 使用录制报告验证接收端能否被 macOS 当作原生妙控板使用。
4. 以上两项通过后，再投入无线链路和 PCB。

不要在 M0 尚未完成时批量购买开发板或制作 PCB。
